# 3D 掷骰动画：外包需求

给 D&D 网页（Vite + React + TypeScript）做一个独立的 3D 掷骰动画模块。它只负责「演」，**点数由我们这边决定**，动画必须停在指定的点数上。

## 效果

- 整个浏览器窗口上盖一层透明画布（`position: fixed; inset: 0`），不挡下面页面的点击（`pointer-events: none`）。
- 摄像机从正上方往下看。推荐用透视，视野角调小（大概 20°–30°），摄像机放得高，这样画面边缘几乎不变形，骰子弹起来又会变大，看得出高度。也可以用正交加明显的阴影。用哪种、具体参数多少，按效果自己调。硬性要求只有两条：
  1. 桌面的边界就在屏幕边缘：屏幕的四条边是「盘子」的四面墙，骰子撞墙会弹回来，不会飞出屏幕。如果用透视，墙按桌面那个高度上视野覆盖的范围放。窗口大小变了，墙跟着变。
  2. 骰子在空中时，要看得出它离桌面多高（靠大小变化或阴影都行），不能看起来像贴着桌面滑。
- 要有阴影，软阴影就够了。
- 骰子从摄像机前面（屏幕上方的一片区域）落下：沿一个大致方向扔出去，初速度、旋转、落点带一点随机，然后滚动、碰撞，最后静止。
- 静止后，朝上那一面就是我们给的点数。过几秒自己淡出；也可以手动清掉。
- 一次可以扔好几颗，最多算 20 颗，比如 8d6。骰子之间要互相碰撞。

## 骰子

- d4、d6、d8、d10、d12、d20，以及 d100（一颗十位骰 00–90，加一颗 d10）。
- d4 的读数方式按常见做法即可（读顶点或读底边，选一种，写清楚）。
- 每颗可以单独指定颜色。字的颜色自动选，保证看得清。
- 优势 / 劣势是同时扔两颗 d20：调用方会标出哪颗作废，作废的那颗停下后变暗。

## 点数必须由我们指定（最重要）

在线模式下由服务器掷骰，客户端只负责播动画，所以点数必须由调用方传进去。

常见做法是先正常跑物理，停下后看哪一面朝上，再把贴图或面编号重新映射一下，让朝上那面显示目标点数。用别的方法也行，但要满足下面三条：

1. 每次都停在给定的点数上。
2. 不能看出骰子被「掰」过去。
3. 同一组输入每次的动画可以不一样，不要求可复现。

## 接口（ESM，不依赖 React）

```ts
export interface DieSpec {
  sides: 4 | 6 | 8 | 10 | 12 | 20 | 100;
  value: number;       // 要停在的点数（d100 是 1–100）
  color?: string;      // '#3b6fb6'
  dim?: boolean;       // 作废的那颗（优势 / 劣势），停下后变暗
}
export interface Dice3D {
  /** 扔一组骰子；所有骰子都静止后 resolve */
  roll(dice: DieSpec[], opts?: { from?: 'top' | 'bottom' | 'left' | 'right' | 'random' }): Promise<void>;
  clear(): void;       // 立刻清掉桌面
  dispose(): void;     // 移除画布、释放资源
}
export function createDice3D(opts?: {
  container?: HTMLElement;   // 默认 document.body
  fadeAfterMs?: number;      // 静止后多久淡出，默认 3000；0 = 不自动淡出
  speed?: number;            // 整体速度倍率，方便调手感
}): Dice3D;
```

- 前一组还在滚的时候又调用 `roll`：两组可以同时在桌面上，也可以把前一组清掉，选一种，写清楚。
- 技术栈不限，建议 three.js 加 cannon-es 或 Rapier。依赖越少越好，打包后最好不超过 1 MB（不含字体）。

## 交付

- 一个文件夹（比如 `dice3d/`）：源码 `index.ts`，加一个能直接打开的 `demo.html`。demo 里要有按钮：各种骰子各扔一颗、8d6、优势 d20、d100。
- 只用 `package.json` 里的 npm 依赖，不用 CDN。
- 性能：普通笔记本上 20 颗骰子保持流畅，从扔出到静止不超过约 2.5 秒。
- 手感需要的参数（重力、弹性、摩擦、初速度范围）集中放在一个配置对象里，方便以后调。

## 不用管

- 掷骰规则、加值、结果显示：这些我们自己做。
- 和我们页面的集成：接口对上就行，我们自己挂进去。
