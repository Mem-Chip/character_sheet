# dice3d：3D 掷骰动画

给它「掷了哪些骰子、每颗是几」，它在页面上演一段 3D 物理滚动，最后停在给定的点数上。动画不决定结果，只负责演。

## 用法

```bash
npm install
npm run dev          # demo 页面（右上角「画面参数」面板可以实时调所有参数）
npm run build        # 库：dist/dice3d.js + .d.ts（three、cannon-es 作为依赖，不打进包里）
npm run build:demo   # 独立 demo：dist-demo/
```

```ts
import { mountDice, rollDice, skipDice, configureDice } from 'dice3d';

const unmount = mountDice(document.body, {
  theme: 'dark',                 // 不传就跟随系统
  camera: { fov: 20, tilt: 16 }, // 其余参数见下文「参数」
});

await rollDice({
  dice: [
    { faces: 20, value: 17, color: '#c0392b' },
    { faces: 20, value: 4, color: '#c0392b', dropped: true },
  ],
  label: 'F5 的攻击（优势）',
  seed: 12345, // 可选
});

configureDice({ theme: 'light' }); // 运行中改参数，只改给出的那些
```

### 接口

| 导出 | 说明 |
| --- | --- |
| `mountDice(container, opts?)` | 挂载全屏透明覆盖层，返回卸载函数。`opts` 是 `DiceOptions`，没给的用默认值 |
| `rollDice(req)` | 播一次，播完（停稳、停留、淡出）后 resolve。连续调用会排队 |
| `skipDice()` | 立刻跳到结果并淡出 |
| `configureDice(patch)` | 运行中改参数（深合并：`{ camera: { fov: 12 } }` 只改 fov） |
| `getDiceOptions()` | 当前生效的完整参数（拷贝） |
| `DEFAULT_DICE_OPTIONS` | 全部默认值 |
| 类型 | `DieSpec`、`RollRequest`、`DiceOptions`、`ResolvedDiceOptions`、`DieKind`、`LabelPosition` |

### 空白骰子（暗骰）

`DieSpec` 加 `blank: true` 时，这颗骰子所有面都不印数字，`value` 可以省略（给了也忽略）。物理照常滚，颜色、`dropped` 变暗照常生效；`faces: 100` 会掷两颗空白 d10。适合 GM 暗骰：其他玩家看得到有人在掷、掷了什么骰，但看不到点数。

```ts
rollDice({ dice: [{ faces: 20, blank: true, color: '#555' }], label: 'GM 暗骰' });
```

TypeScript 类型上，普通骰子仍然必须给 `value`，只有 `blank: true` 时才能省略。

页面上带 `data-dice-noskip` 属性的元素（及其子元素）里点击**不会**触发跳过，适合聊天输入框、设置面板等。

## 参数

所有参数都可选。超出范围的值会被截到范围内，不会报错。

`configureDice` 生效时机：镜头、灯光、影子、主题、label 位置、分辨率**立即生效**（播放中也会变）；粗糙度对正在播的骰子也立即生效；其余（颜色、弃骰变暗、时长、物理）从**下一次**掷骰开始。

### 镜头 `camera`

| 参数 | 默认 | 范围 | 说明 |
| --- | --- | --- | --- |
| `fov` | 20 | 1–90 | 视场角（度）。越小透视越弱，越接近正交俯视 |
| `tilt` | 16 | 0–80 | 镜头偏离正上方的角度（度）。0 = 正俯视 |
| `fill` | 0.95 | 0.2–1 | 桌面占屏幕的比例（宽高里更紧的那个方向） |

镜头距离是自动算的：给定 fov 和 tilt，把整张桌面刚好装进 `fill` 比例的屏幕。

可能的问题：
- **fov 很小（< 8°）**：几乎没有透视，立体感变弱；骰子弹起来时也不会变大，看起来“扁”。镜头会退得很远，近/远裁剪面已经跟着调整，不会被裁掉。
- **fov 很大（> 45°）**：边缘的骰子会被明显拉伸变形；骰子弹起时离镜头近，会突然变得很大。
- **tilt 很大（> 35°）**：远处的骰子明显变小，顶面被斜着看，数字压扁，**读数会变难**；靠近镜头一侧的骰子弹起来可能挡住后面的。tilt = 0 时 d4 三面都斜着，字略难读。
- **fill 接近 1**：骰子弹得高时会短暂超出屏幕边缘（计算只算了桌面上方 1.2 的高度）。
- 窄屏（手机竖屏）：桌面是横的，按宽度装进来后骰子会比较小。可以配合较小的 `physics.tableWidth` 使用（注意那会影响同步，见下）。

### 灯光 `lighting`

| 参数 | 默认 | 范围 | 说明 |
| --- | --- | --- | --- |
| `ambient` | 1.6 | 0–10 | 环境光（半球光）强度 |
| `sun` | 2.2 | 0–10 | 主光（平行光，产生影子）强度 |
| `shadowOpacity` | 按主题 | 0–1 | 影子浓度。不给时：浅色主题 0.28、深色 0.5 |

可能的问题：
- `ambient` 太低：背光的面接近全黑，侧面数字看不清；对深色骰子尤其明显。
- `ambient + sun` 太高：浅色骰子（白、黄）亮面过曝成一片白，**白底黑字的数字对比度下降**。
- `sun = 0`：没有影子，也没有明暗，骰子看起来像贴纸。
- 影子浓度在深色背景上调低会几乎看不见；浅色背景调太高会显得脏。影子画在透明层上，背景颜色由你们的页面决定，所以这个值最好跟着地图底色调。

### 外观 `look`

| 参数 | 默认 | 范围 | 说明 |
| --- | --- | --- | --- |
| `defaultColor` | `#4f5bd5` | hex | `DieSpec.color` 没给时用的颜色 |
| `roughness` | 0.42 | 0–1 | 表面粗糙度，越小越亮、高光越强 |
| `droppedBrightness` | 0.4 | 0–1 | 弃骰（`dropped`）变暗后的亮度，1 = 不变暗 |
| `droppedOpacity` | 0.6 | 0–1 | 弃骰变暗后的不透明度，1 = 不透明 |
| `labelPosition` | `top-left` | 四个角 | label 显示在哪个角 |
| `maxPixelRatio` | 2 | 0.5–4 | 渲染分辨率上限（相对 CSS 像素） |

可能的问题：
- `roughness` 太低（< 0.2）：主光照到的面会出现一大块高光，**正好盖住朝上那面的数字**。
- 弃骰亮度和不透明度都调到 1：弃骰和保留的骰子没有区别。不透明度太低：弃骰几乎看不见，玩家可能以为少掷了一颗。半透明的骰子叠在一起时偶尔会有排序穿插（WebGL 透明物体的通病）。
- `labelPosition` 和你们页面上固定在角落的 UI（工具栏、聊天框）可能重叠；label 在覆盖层上，不挡点击，但会挡视线。
- `maxPixelRatio` 调高（3–4）：在高分屏上更清楚，但 GPU 负担按平方增长，集显笔记本可能掉帧；调低（1 以下）会糊。
- 颜色：数字颜色是按骰子颜色的亮度自动选黑或白，中等亮度的颜色（比如纯绿、橙）对比度会弱一些。`defaultColor` 写成非法 hex 时退回内置的蓝色。

### 时长 `timing`（毫秒）

| 参数 | 默认 | 范围 | 说明 |
| --- | --- | --- | --- |
| `maxRollMs` | 2300 | 200–10000 | 滚动最长播多久。物理过程更长就加速播放 |
| `holdMs` | 1000 | 0–20000 | 停稳后停留多久再淡出 |
| `skipHoldMs` | 650 | 0–20000 | 跳过后停留多久再淡出 |
| `dimMs` | 300 | 0–5000 | 弃骰变暗用时 |
| `fadeMs` | 400 | 0–5000 | 淡出用时 |

物理过程本身一般是 1.4–3.3 s（骰子越多越长），只加速、不减速。

可能的问题：
- `maxRollMs` 太小（< 1500）：物理过程被压缩播放，**看起来像快进**，骰子的运动不自然。太大（> 3500）不会让动画变慢（物理本身就那么长），只是不再加速。
- `holdMs` 太小：结果停留时间不够，玩家来不及看清。多人跑团里结果通常还会在聊天栏显示，可以适当缩短。
- `holdMs` / `skipHoldMs` 很大：排队的掷骰会积压，后面的要等很久才播。`rollDice` 的 Promise 也要更久才 resolve。
- `dimMs` 比 `holdMs` 还长：变暗还没完成就开始淡出。
- 保险时限会随这些值自动变：`maxRollMs + max(holdMs, skipHoldMs, dimMs) + fadeMs + 3000`，到点一定结束。

### 物理 `physics`（⚠ 会改变滚法）

| 参数 | 默认 | 范围 | 说明 |
| --- | --- | --- | --- |
| `tableWidth` | 17 | 4–200 | 桌面宽（世界单位；d6 边长约 1） |
| `tableDepth` | 10.6 | 4–200 | 桌面纵深 |
| `tableGrow` | true | — | 骰子多于 9 颗时按 √(n/9) 放大桌面（镜头跟着拉远） |
| `dieScale` | 1 | 0.2–5 | 骰子大小倍数。一个数 = 全部，或按面数分别给：`{ 4: 1.2, 20: 0.9 }` |
| `layFlat` | true | — | 物理停下后，把斜靠/叠起来的骰子放平 |
| `maxDice` | 20 | 1–100 | 一次最多几颗实体骰子（d100 算 2 颗），多的忽略 |

**同步**：除 `maxDice` 外，这些参数会改变物理过程。多人同步时**各端必须用一样的值**，否则同一个种子各端看到的滚法不同。**最终点数仍然一定正确**，只是过程和落点不一样。外观、镜头、时长参数各端可以不同。

可能的问题：
- **桌面太小 / 骰子太多 / 骰子太大**：骰子会叠成一堆，大量骰子需要最后“放平”，看起来像被挪开；极端情况下放平后的位置找不到空地，**骰子会互相穿插**。起始时排不下的骰子会往上叠一层再扔，第一下会更乱。
- **桌面太大**：骰子扔不到对面就停了，大部分区域空着，骰子在屏幕上显得小。初速度会随桌面宽度略微增大，但不会无限增大。
- **`dieScale` 很大**：重力不变，所以大骰子看起来像**慢动作**、轻飘飘的；物理计算更慢（接触点多）。很小（< 0.5）则数字在屏幕上太小，读不清。按面数分别给的时候，大小差很多的骰子互相碰撞会把小的撞飞。
- **`tableGrow: false` 且骰子多**：同「桌面太小」。
- **`layFlat: false`**：不再有最后的“挪一下”，但斜靠在别的骰子或墙上的骰子会**保持斜着**，朝上的是哪一面肉眼可能有争议（程序取的是法线最朝上的面，点数仍然正确）。
- **`maxDice` 调大**：物理预计算耗时随骰子数超线性增长，60 颗 d6 实测约 80 ms，40+ 颗 d12/d20 可能接近 1 s 卡顿；渲染也更重。

## 为什么有的骰子最后会“跳一下”

这是 `layFlat` 在起作用。物理停下后，偶尔有骰子**斜靠在另一颗骰子上**、**叠在别的骰子上面**，或者**卡在墙边**。这时朝上的是哪一面不明确，所以在最后 0.3 s 里把它放平；如果它下面压着别的骰子，就顺便挪到旁边空地上，挪动时会稍微抬起一点避免穿过邻居。

实测频率（每种情况 20 次随机）：

| 骰子数 | 被明显挪动（倾斜 > 5° 或横向移动）的骰子占比 |
| --- | --- |
| 1 颗 | 0–5% |
| 2 颗 | 0–15% |
| 8 颗 | 5–25%（d6 最少，d4、d12 最多） |
| 20 颗 | 5–30% |

骰子越多越挤，越容易互相靠着。想减少：加大桌面（`tableWidth/tableDepth`）、缩小骰子（`dieScale`）；想完全不要：`layFlat: false`（代价见上）。

早期版本里，这个“跳”远比现在频繁：几乎每颗骰子停下前都会抬起再落下。原因有两个，都已修好：
1. cannon-es 自带的睡眠判定只看速度，会把正在慢慢翻过棱的骰子冻在斜角上（常常 10–30°）。现在改为自己判定：位置和角度都几乎不变，**并且**平放才算停稳；没平放的要静止更久（约 0.33 s）才算。
2. 放平时不管需不需要都抬高 0.25。现在只有横向挪开时才抬，抬多高按挪多远算，原地放平完全不抬。

## 怎么保证停在给定点数

1. 用 cannon-es 把整段物理过程**先算完**（固定步长 1/60 s，全部骰子停稳或到 3 s 为止），记下每帧位姿。
2. 看每颗骰子最后哪一面朝上（d4 看朝上的顶点），把那一面的数字和目标数字**对调**，然后才生成贴图。整个动画用的都是对调后的贴图，过程中不会有数字跳变。
3. 结果是由构造保证的，不依赖物理的随机性：不管物理怎么滚，朝上那面都是目标点数。

附带处理：
- **结果面突出**：朝上那面的数字画得更实、稍大，其余面稍淡，停稳后一眼能看到结果。
- 所有骰子（d4 除外）的 6 和 9 都加下划线。
- d10 用 1–10；d100 = 十位骰（00–90）+ 个位骰（0–9），100 显示为 00 + 0。

## 种子

同一个 `seed` + 同样的骰子列表 + 同样的 `physics` 参数 → 同样的初始抛掷和同样的物理过程。桌面大小只由参数和骰子数决定，与屏幕尺寸无关，镜头再按屏幕去适配桌面，所以不同分辨率的客户端算出的轨迹一样。
注意：跨浏览器引擎时，`Math.sin` 这类函数可能在最后一位上有差别，长时间的混沌过程可能因此分叉。**最终点数永远正确**，只是过程不一定逐帧相同。

## 行为细节

| 项目 | 实现 |
| --- | --- |
| 跳过 | 点击页面任意处（`data-dice-noskip` 里的除外）或按 Esc：滚动中会直接跳到最终结果，停留 `skipHoldMs` 后淡出；停留中则直接淡出。只影响当前这次，排队的照常播 |
| 排队 | 连续调用 `rollDice` 会依次播放，每个 Promise 在自己那次播完后 resolve |
| 覆盖层 | `position: fixed; inset: 0; pointer-events: none`，不挡下面的地图和按钮 |
| 减少动态效果 | `prefers-reduced-motion: reduce` 时不滚：骰子直接摆在桌面中间，结果面朝上、字正对屏幕，停留后淡出 |
| CPU | 只有在播的时候才跑渲染循环，播完就停 |
| 后台标签页 | 标签页隐藏时到来的掷骰直接 resolve、不播；播放中切走就立即结束（不然回来时会一口气补播一堆） |
| 保险 | 每次播放到时限一定结束（比如窗口被遮挡导致 rAF 暂停），队列不会卡死 |
| 非法输入 | 点数越界会截到 1..faces 并 `console.warn`；不支持的面数会跳过；参数越界截到范围内 |
| 资源 | 无外部资源：数字贴图在 canvas 上用系统字体程序生成 |

## 性能（在开发机上实测，默认参数）

物理是在动画开始前同步算完的，主线程一次性花费：

| 场景 | 预计算耗时 |
| --- | --- |
| 1–2 颗任意骰子 | 1–11 ms |
| 8 颗 | 12–130 ms |
| 20 颗 d4/d6/d8/d10 | 27–125 ms |
| 20 颗 d12/d20（最差情况） | 280–350 ms |

这段时间里页面不会有动画在播，所以看不出卡顿，但在骰子很多时，主线程会被占用一小下。如果以后要更顺，可以把 `simulate()` 挪进 Web Worker（它只依赖 cannon-es 和几何数据，输出是一个 `Float32Array`）。

`dieScale` 每换一个新值会生成并缓存一份几何体；在 demo 面板里拖滑块会缓存很多份（每份几 KB），正式使用时值是固定的，不受影响。

## 文件

- `src/index.ts`：对外接口、渲染、播放状态机
- `src/options.ts`：参数类型、默认值、范围截断
- `src/sim.ts`：cannon-es 物理预计算、停稳判定、最后的放平处理
- `src/geometry.ts`：七种骰子的几何体（由顶点自动求面）、贴图布局
- `src/atlas.ts`：每颗骰子的数字贴图
- `index.html` + `demo/main.ts` + `demo/tune.ts`：demo 页面和参数面板
