# 数据化工作包（给 AI 代理用的说明）

把 D&D 2024 的规则原文写成规则引擎能执行的 JSON。你要做的事：**逐条读任务 → 写答案文件 → 跑检查命令 → 没过就改**，全部做完后收集、检查、跑测试。

所有命令都在**仓库根目录**运行（这个文件夹的上一级）。需要 Node 22+，第一次先 `npm install`。

## 一、这里有什么

| 文件夹 | 内容 | 要做的 |
|---|---|---|
| `batch-w2-spells/` | 2024 玩家手册的法术，384 条，分 44 批（`batches.json`） | **全部要做** |
| `batch-w1-features/` | 职业 / 子职特性、专长、可选特性、种族，545 条 | 已经做完了，只剩 `retry.md` 里列的 13 条要重做 / 改进 |
| `batch-w3-books/` | 玩家手册以外的书：XGE、TCE、AU、FRHoF 的子职（68 个）、专长、可选特性、种族、法术，687 条，分 88 批 | **全部要做**（建议在法术之后做，法术里的写法可以直接参考） |
| `batch-w4-items/` | 物品：2024 魔法物品（XDMG）+ 玩家手册的冒险装备、药水（XPHB），525 条，分 55 批 | **全部要做**（新的一波，看下面「物品的注意事项」） |
| `redo-instance/` | 重做：用上动作实例和菜单选择的 462 条（审查里标出来的），分 60 批 | **全部要做**，说明看它自己的 `README.md` |
| `instance-audit/` | 审查（不写数据）：1010 条没完全自动化的条目，逐条记要从触发它的那次动作里读什么、做什么，用来定「动作实例」的形状 | 说明看它自己的 `README.md` |
| `redo-zones/` | 重做：区域 / 困难地形相关的 74 条已有 AI 数据（引擎加了新的区域写法） | **全部要做**，说明看它自己的 `README.md` |

每个文件夹里：

- `spec.md` —— **写法说明，开工前完整读一遍**。里面有格式、表达式能用的名字、每个时机能用什么、引擎的执行细节、资源池怎么声明、什么时候该跳过。
- `examples.json` —— 手写的标准答案（几十条，都有场景测试）。照着它们的风格和粒度写。
- `tasks/<题号>.md` —— 一条任务：原文、职业表、可以花的资源、接口要求。（`.ctx.json` 是给检查程序用的，不用看。）
- `answers/<题号>.json` —— 你写的答案放这里。
- `batches.json` —— 分批：同一批里是同一组（同一个职业、同一环法术），做的时候一批一批来，保持写法一致。
- `manifest.json` —— 题号 → 条目键的对照。

## 二、做一条任务

1. 读 `tasks/<题号>.md`。
2. 写答案到 `answers/<题号>.json`。两种写法：
   - 一个条目（格式见 `spec.md`，例子见 `examples.json`）；
   - 或者跳过：`{ "skip": "一句话原因" }`。纯静态的（人物卡已经算了的熟练、加值）、纯叙事的、只是目录 / 授予别的条目的，都应该跳过。
3. 检查：
   ```bash
   npx tsx tools/factory/batch.ts lint datafy/batch-w2-spells S001
   ```
   （特性那边把目录换成 `datafy/batch-w1-features`，题号是 `F` 开头的。）
   输出 `✓ 通过` 或 `✓ 跳过` 就好了；`✗` 会列出问题，改完再跑，**最多改 4 轮**，还不过就改成 `automation: "partial"` / `"manual"` 或者跳过。

## 三、原则

- **宁可 skip、partial、manual，也不要写错**。引擎做不到的部分写进 `text` 说明，标成部分自动化。
- 原文里**隐含的自动规则**也要写出来（比如「攻击敌人时狂暴自动延长」）。
- **同一批保持一致**：资源 id、效应名、标签名在同一个职业 / 同一组法术里要一样。
- 需要新的次数池（「每次长休一次」）才在答案顶层写 `resources` 声明（见 `spec.md`）；任务里列了的资源直接用，不要重复声明。
- 法术的升环：伤害骰写成 `(2 + slot.level)d6` 这种，跟着原文的「每高一环」算；戏法按角色等级增长见 `spec.md`。
- **只写 `answers/` 里的文件**。不要改仓库里的其他文件（引擎代码、手写数据、测试）。觉得引擎缺了某种能力，记到 `datafy/notes.md` 里（写清楚是哪条、缺什么）。

### 物品的注意事项（`batch-w4-items`）

- 条目键是 `<来源>:item:<名字>`；lint / collect 用法一样，结果写进 `data/dyn/ai/items.json`。
- **生效条件**：装备着的物品（需要同调的还要已同调）的条目才生效；消耗品带在身上就能用。不用自己写「是否装备」的条件。
- **固定加值不要写**：+N 武器 / 护甲、AC、豁免、法术攻击 / DC 的固定加值，人物卡已经从物品数据里算了。物品只有这些就 `{ "skip": "固定加值，人物卡已处理" }`。
- **三种「次数」，id 照任务里给的写**：
  - 消耗品的数量：`cost: [{ resource: '物品:<名字>' }]`（任务里列了才有）；
  - 充能：`cost: [{ resource: '物品充能:<名字>', n: 几发 }]`（任务里列了才有），**不要**声明 resources；
  - 没有充能、但「长休 / 黎明前只能用一次」：在条目顶层声明 `resources: [{ id: '物品次数:<名字>', name: '…', formula: 1, recovery: 'long' }]` 再在 cost 里花它。
- 喝药水是附赠动作；投掷类消耗品（炼金火、圣水、强酸瓶）是一次攻击或豁免，照原文写。
- 「消耗充能施展某个法术」：照那个法术的效果写成动作（可以参考 `data/dyn/ai/spells.json` 里同名法术的写法）；DC 物品写了数值就用数值。
- 纯叙事、探索用的（绳索、帐篷、照明、通讯、变形、坐骑……）跳过。
- 神器、传说物品花活多：能写的部分写，其余 `automation: "partial"` 并在 text 里说明。

### 其他书的注意事项（`batch-w3-books`）

- 条目键的第一段是书的缩写（`XGE:法师:魔力潮涌:6`、`TCE:spell:…`），lint / collect 的用法完全一样；结果写进 `data/dyn/ai/books.json`。
- 这些书**没有人物卡层的数据**（`data/abilities-2024.json` 只覆盖 2024 核心书），所以任务里「可以花的资源」常常是空的。原文里有「每次长休 N 次」之类的次数，就在答案顶层 `resources` 里声明（见 `spec.md`）；同一个子职的几条要用同一个资源 id。
- 老书（XGE、TCE）的子职是站点改给 2024 职业用的版本，个别特性的等级还是老版的（比如 2 级），照任务里写的等级来，不要自己改。

## 四、收集

一批（或者全部）做完后：

```bash
npx tsx tools/factory/batch.ts collect datafy/batch-w2-spells
```

它会把每份答案再检查一遍，并在一场模拟战斗里真的跑一遍（用掉所有动作、被攻击、做豁免、过几个回合），然后：

- 通过的写进 `data/dyn/ai/spells.json`（特性是 `data/dyn/ai/features.json`），标「AI 生成、未审」；
- 答案里声明的新资源池写进 `data/abilities-2024.json`；
- 没过的列在 `<目录>/failures.json`，带着问题 —— **照着问题改答案，再 collect**，直到没有失败或者只剩确实写不了的（那些改成 manual 或 skip）。

collect 可以反复跑，每次都会按 answers 里的最新内容重新生成。

## 五、检查（做完之后自己审一遍）

检查程序只保证「格式对、跑起来不出错」，不保证「写得对」。每一批做完，回头对照原文抽查，重点看：

- 数字：伤害骰、DC、射程、范围大小、持续时间、次数；
- 豁免用的属性、伤害类型、成功时减半还是无效；
- 升环、戏法随等级增长；专注；仪式；
- 目标：单体 / 多个 / 范围，敌我；
- `automation` 标得诚实：手动处理的部分写清楚了吗。

发现的问题直接改答案再 collect。审完在 `datafy/review.md` 里写几行：查了哪些、改了什么、还有哪些拿不准。

## 六、最后

```bash
npm test
npm run check:data
```

- `npm test` 里只有「角色快照」测试失败、而且差别只是多了新的资源池（`_resources` / `_derived.resources` 里多出来的条目）的话，这是预期的：跑 `npm run snapshots` 更新快照，再跑一遍 `npm test`。
- 其他测试失败：不要去改测试，把失败信息记到 `datafy/notes.md`。

做完之后汇报：每个文件夹写了多少、跳过多少、没过多少，`notes.md` 和 `review.md` 里的要点。不用提交 git，人会看过之后再提交。

## 七、附：怎么从 5etools 抓更多的书

数据来自 5etools 的中文镜像 `https://5e.kiwee.top`（想换镜像就设环境变量 `DND_DATA_BASE`）。缓存在 `data/5etools/`（不进 git）。

**站点的数据是怎么放的**

| 内容 | 文件 | 说明 |
|---|---|---|
| 法术 | `/data/spells/index.json` → `/data/spells/spells-<书>.json` | **每本书一个文件**，index.json 是「书的缩写 → 文件名」 |
| 职业、子职、职业 / 子职特性 | `/data/class/index.json` → `/data/class/class-<职业>.json` | 一个职业一个文件，**里面已经有所有书的子职** |
| 专长、可选特性、种族、背景、物品 | `/data/feats.json`、`optionalfeatures.json`、`races.json`… | **所有书在一个文件里**，靠每条的 `source` 区分 |
| 怪物 | `/data/bestiary/index.json` → `bestiary-<书>.json` | 每本书一个文件（这次不做） |

每一条都有 `source`（书的缩写）。两个要注意的字段：

- `reprintedAs`：这一条在新书里重印过（比如塔莎的「星辰结社」→ 2024 玩家手册）。**有这个字段的不做**，做重印后的那一版。
- 子职的 `classSource`：老书的子职有两份，`PHB` 是给 2014 职业的，`XPHB` 是站点改给 2024 职业的。**只做 `XPHB` 那份**。改版的那份只重写了少数几条特性，其余沿用老版（`classSource = PHB`）的特性 —— 出题程序已经处理了。

**加一本书**

```bash
# 1. 抓数据：法术按书抓；职业、专长、可选特性、种族的文件本来就是全的
BOOKS=XGE,TCE,AU,FRHoF,EGW npx tsx tools/fetch-data.ts
# 2. 出题：排除重印过的和已经做过的（已经在 data/dyn/ 里的不会再出）
BOOKS=EGW npx tsx tools/factory/batch.ts plan 3 datafy/batch-w3-egw
```

然后照第二到第六节做。新文件夹名里必须有 `batch-w3`（collect 靠它认这是哪一波）。书的缩写看站点的 `/data/spells/index.json`、`/data/class/class-*.json` 里的 `source` 字段，或者 5etools 网页上每条右下角的来源。
