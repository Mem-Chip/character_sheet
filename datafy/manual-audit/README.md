# 审「回退到手动」的条目：缺了哪些引擎接口

规则数据里有 921 条没有完全自动化（`automation` 是 partial / manual，或者执行树里用 `note` 代替了真效果，比如反冲术把减伤写成一句 note）。要搞清楚**是引擎缺了什么接口**，好按重要性补。

- `list.md`：全部条目，人看的版本。6 环及以上法术放在最后，**不用审**。
- `parts/P01.json` … `P17.json`：要审的（每份 50 条，不含 6 环及以上）。每条有：键、名字、automation、环阶（null = 不是法术）、说明里提到手动的句子（`manual`）、执行树里的 note（`notes`）。
- 条目全文在 `data/dyn/ai/*.json`、`data/rules-2024.json`（按键找）。写法说明在 `datafy/batch-w3-books/spec.md`：**先读第 2、4、6 节**，判断「现在能不能写」要靠它。

## 每条要判断什么

答案写到 `answers/P01.json`（和 parts 同名），是一个数组，每条一个对象：

```json
{ "key": "FRHoF:spell:反冲术", "scope": "combat", "gap": "reactModify", "need": "反应法术的 root 里不能改正在结算的伤害包（要 reduceDamage）", "now": false }
```

- `scope`：
  - `combat`：战斗里会用到，值得自动化；
  - `manual-ok`：叙事、探索、长时间、社交、休息时的，手动很正常，不用做；
  - `rare`：战斗里有，但很少见或太复杂（花活多），手动可以接受。
- `gap`：缺的是哪一类接口，从下表挑一个；都不合适就写 `NEW:一个短名字`，并在 `need` 里说清楚。
- `need`：一句话，具体缺什么（要能看出引擎该加什么）。
- `now`：`true` = **现在的写法其实能做到**，是答案写得不够（顺手在 `fix` 字段写一句该怎么改）；`false` = 确实缺接口。

| gap | 意思 |
|---|---|
| `reactModify` | 反应 / 触发时改正在结算的东西：减伤、改命中、打断施法、改豁免结果 |
| `source` | 效果要落在伤害来源 / 攻击者 / 施法者身上，但拿不到这个人 |
| `remember` | 效应要记住施放时的数（环阶、掷出的骰、选的伤害类型）以后用 |
| `healByDamage` | 按造成 / 受到的伤害回血、给临时生命值 |
| `summon` | 召唤生物、随从、魔宠入场和它们的行动 |
| `zone` | 地图上持续的区域：进入 / 在里面开始回合时生效，墙、雾、困难地形 |
| `move` | 强制位移、传送、改速度、飞行 |
| `vision` | 视线、隐形、光照、掩护、看不看得见 |
| `item` | 物品、武器、护甲、装备的变化 |
| `choice` | 要人在几项里选（伤害类型、选项菜单）而现在选不了 |
| `resource` | 资源 / 法术位的特殊花法、返还、跨条目共享 |
| `condition` | 状态 / 效应本身的规则（魅惑、擒抱……）引擎没管 |
| `timing` | 缺某个时机（窗口 / 事件）可以挂 |
| `other` | 其他 |

## 交付

1. 先建 `answers/` 文件夹。17 份都写完后跑 `npx tsx tools/factory/manual-audit.ts merge`，它会检查格式并生成 `report.md`（按 gap 汇总、计数、列 `now: true` 的）。
2. 在 `report.md` 末尾手写一节「建议」：按重要性排前 10 个该补的接口，每个说影响多少条、举 2～3 个代表条目；另外列你觉得**我们忘了、但应该有**的东西（不一定在这 921 条里）。
3. 不要改 `data/` 下的规则数据；`now: true` 的只写 `fix`，之后统一改。
