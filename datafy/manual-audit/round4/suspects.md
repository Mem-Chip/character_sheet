# 第四轮：复核挑出的 5 条（证据 + 结论）

都还缓着、没合并。下一轮照这里的证据改。

## 1. `TCE:德鲁伊:召唤野火精魂:2`

代理写「生命值降为 0 时引擎会自动消失」，但**实测 0 血只是被标成死亡、棋子仍留在遭遇里**
（`damage.ts` 的 `kill()` 只发 `deadChanged` / `died`；`combatantRemoved` 只在专注结束 `effects.ts:412` 与同组顶替 `exec.ts:368` 时发）。
→ 文本应改成「请手动移除」。

## 2. `XPHB:spell:咒唤林地卫士`

两处：
- 原文是「你可以迫使」（可选），但回合结束那次豁免写成了**强制触发器**（没有 `optional`）。实测队友在光环里结束回合被自动扣 27 点力场伤害，全程没问过要不要生效 ——「不该打的那次请撤销」这个说法自相矛盾。
- ③ 说「你可见的生物引擎不判断」，但 `scope.ts` 的 FUNCS 里 `canSee` 是现成的、说明书 L143 明确要求用它 —— 不是做不到。

## 3. `XPHB:链之魔契`

文本让玩家「用图鉴把怪物加进来当魔宠，然后把默认数据那一只删掉」，但**带 `familiar` 标签的动作在界面上会直接打开图鉴选形态框**
（`app/pages/combat/Actor.tsx:471` → `Dialogs.tsx:499`），选中形态由 `exec.ts` 的 `ctx.form` 顶替召唤数据 —— 没有「默认数据那一只」可删。
照它做会多加一只不在 `XPHB:spell:寻获魔宠` 组里的魔宠，破掉条目自己写的「同一时间只能有一只」顶替规则。

## 4. `XPHB:哨兵`

正文和两条 note 都写「引擎不知道你拿的是什么武器，所以打不了这一下」，但 `space.ts:135-141` 的借机攻击弹窗**就是按近战武器列「借机攻击：<武器名>」的** —— 引擎知道武器。
真正的原因是守护者的两个时机没接进借机攻击流程（行为描述对，给的原因编的）。

## 5. `XPHB:吟游诗人:灵感织衣:3`

两处：
- `tempHp` 节点写了 `"to": "each"`，但 `types.ts:263` 的 `tempHp` 只接受 `NodeTarget`（`target|self|attacker`），`'each'` 只有 `applyEffect` 才允许（`types.ts:265`）；
  现在只是 `exec.ts` 的 `recipients` 恰好也认，`lint` / `audit` 查不出来。→ **检查器该补一条**（`tempHp`/`heal` 的 `to` 不接受 `'each'`）。
- `诗人骰 + 诗人骰` 掷的是**两颗独立骰**，不是原文「两倍该诗人骰骰值」；引擎记下的临时生命值与文本让人「按第一次掷出的值口头统一」对不上。
